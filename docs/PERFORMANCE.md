# 性能验收

Nooklet 的第一约束是尽量低的常驻内存、CPU 和能耗。下列目标需要实机长测。

## Nooklet 0.3.0 短测

在 M2 Pro、16 GB、macOS 27.3 上运行 Release 构建。切换系统状态和灵动岛设置后关闭两个展示面，并收起工具箱。进程物理内存为 35.2 MB，15 秒内累计 CPU 时间未出现可测变化。长时间驻留和屏幕顶部状态条开启时的功耗仍需测量。

## Nooklet 0.2.0 短测

2026-11-12 在 M2 Pro、16 GB、macOS 27.3 上测试 Release 版。使用系统状态、IP 查询和存储扫描后收起窗口，计时器为暂停状态。进程物理内存占用为 32.7 MB，进程峰值为 35.0 MB。20 秒内 `ps` 的累计 CPU 时间读数和会话文件均保持不变。CPU 读数受 `ps` 的显示精度限制。长时间空闲、唤醒和 WindowServer 开销仍需实测。

## LiteBox 基础工程短测

2026-11-12 在 M2 Pro、16 GB、macOS 27.3 上运行 Release 应用，打开控制窗口后收起到菜单栏，保留一个运行中的计时器。`vmmap -summary` 报告进程物理内存占用为 26.5 MB。20 秒内 `ps` 未显示累计 CPU 时间增长，`configuration.json` 的文件标识、修改时间和大小保持稳定。CPU 时间受 `ps` 的显示精度限制。10 分钟基线、8 小时稳定性、唤醒与 WindowServer 开销需要按下文口径继续测量。

## 初始目标

基准机建议为 M1、8 GB 内存。每次记录实际机型、内存、macOS 版本、显示器数量与缩放、供电状态和构建版本，不能将不同机器的结果直接混为一次对比。

| 场景 | 内存目标 | CPU 目标 |
| --- | --- | --- |
| 空宿主、没有展开界面 | 所有自有进程物理内存占用合计 ≤40 MB | 10 分钟平均 ≤0.2% |
| 三个低频插件，无展开界面 | 合计 ≤70 MB | 10 分钟平均 ≤0.5%，应尽量接近空宿主 |
| 交互、导入、更新 | 单独记录峰值 | 单独记录总 CPU 时间与 P95 交互延迟 |
| 固定场景运行 8 小时 | 无持续增长趋势 | 无无意义周期性负载 |

CPU 百分比以占满一个逻辑核心为 100%。使用 Release 构建、无调试器连接；诊断工具的采样本身有开销，应将低干扰基线测量与深入剖析分开。

## 测试场景

1. **冷启动：** 记录进程启动至状态栏可交互的时间、启动期峰值内存和 CPU 总时间，检查启动时是否执行无必要读盘或扫描。
2. **空闲：** 启动后稳定下来，连续记录 10 分钟。菜单栏面板和灵动岛均关闭，观察后台唤醒、磁盘与网络活动。
3. **状态展示：** 分别测仅打开面板、仅显示灵动岛和两处同时开启。
4. **使用后空闲：** 打开管理界面、操作、关闭，再测 10 分钟。关闭窗口不保证框架和缓存马上归还内存，因此必须单独记录此场景。
5. **重复操作：** 重复开关面板、启动暂停重置、导入升级。预热后对比各轮内存，定位对象或订阅残留。
6. **休眠恢复：** 显示灵动岛后休眠再唤醒，确认状态恢复且没有补跑刷新或写盘任务。
7. **长时间运行：** 固定插件和数据，记录 8 小时变化。区分必要数据增长、稳定缓存和不断积累的泄漏。
8. **显示环境：** 测深浅色、多显示器、切换 Spaces 和全屏应用；未来加入挂件和灵动岛后补充遮挡及不可见状态。

三插件场景同时安装系统状态、IP 检测和存储分析。空闲场景关闭窗口，另测各工具打开、切换、扫描取消与使用后空闲。

## 计量范围与工具

- 将主进程与关联的辅助进程、扩展共同计入。
- 以内存诊断工具的物理占用口径为准。`ps` 的 RSS 适合粗略趋势观察，不能直接当作 physical footprint，也不能与虚拟地址空间大小混用。
- 记录 WindowServer 的系统级增量。其占用受其他应用与显示环境影响，使用相同场景对照 Nooklet 开启与关闭。
- 用 Instruments Time Profiler 定位计算热点，用 Allocations 的 generations、Memory Graph 与 Leaks 检查残留；结合 Activity Monitor 的 CPU、Energy、Disk 和 Network 观察。
- 记录 timer wakeups 与后台唤醒。空闲时没有产品价值的重复唤醒需要解释和消除；必要 timer 设置容差并在不需要时取消。

可使用下面的低频观察命令查看一个已知进程的 CPU 与 RSS，结果只用于诊断线索，不作为最终验收报告：

```sh
ps -p <PID> -o pid=,etime=,%cpu=,rss=,comm=
```

RSS 单位为 KiB；单次 `%CPU` 也不是预先定义的 10 分钟场景平均值。正式 CPU 平均值可以用测量窗口内累计 CPU 时间的增量除以墙钟时间，并将所有相关进程相加。

## 不可牺牲的实现约束

- 不为每个插件启动永久进程、轮询器或脚本引擎。
- 状态采样仅保留在内存中。可从菜单栏打开的状态面板关闭后，后台约每 5 秒更新已选指标，进程采样间隔至少 10 秒。
- 界面不可见时停止对应渲染、动画和无必要采样。
- 状态按需、局部更新，状态数值变化只刷新对应卡片。
- 实时监控、曲线和持续动画有固有开销，必须单独定义采样率和可见性策略；不能声称此类模式零耗电。
- 新功能若使基线超预算，先定位和收缩实现，不用“以后优化”替代验收。

参考 Apple 的 [减少定时器](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/Timers.html)、[能耗最佳实践](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/BestPractices.html) 和 [内存分析](https://developer.apple.com/documentation/xcode/gathering-information-about-memory-use)。
