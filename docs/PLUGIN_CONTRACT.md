# 声明式插件契约 v1

插件是宿主读取的受约束数据包。它不携带需要动态加载的 Swift、原生库或 JavaScript 代码。首版将插件独立开发和更新能力限制在宿主已经实现的模板范围内，以控制常驻开销和系统能力暴露。

## 文件与字段

导入来源可以是 `.plugin` 目录或文件名为 `manifest.json` 的文件。只读取和安装清单；其他文件不会执行或复制。

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 整数 `1` |
| `hostAPIVersion` | 整数 `1` |
| `id` | 1–100 个 ASCII 字节；小写字母、数字、点、连字符；首尾必须为字母或数字，不能包含连续点 |
| `version` | 三段非负整数，例如 `1.2.0`；各段最多 `999999`，除数字 `0` 外不能有前导零 |
| `name` | 非空，最多 80 个字符 |
| `description` | 最多 1000 个字符 |
| template | systemStatus、ipLookup、storageAnalysis、lanShare、menuBar、cooling、finderTools、appDiagnostics 或 island |

`cooling`、`appDiagnostics` 和 `island` 的清单可读取，对应的工具箱入口暂未开放。

清单最多 64 KiB，符号链接来源被拒绝。插件 ID 不能直接变成任意路径，实际安装路径固定在宿主的 `Plugins` 子目录中。

## 更新与数据

宿主用 ID 判断插件身份。同一 ID 的安装包须提高版本号并保留模板。导入先校验，再原子写入，失败时保留已安装清单。

插件清单单独保存。应用将菜单栏与灵动岛的显示偏好写入 display.json。更新需保留插件 ID 和模板。系统能力与布局由宿主版本管理。

首版仅支持用户主动导入本地文件，尚未建立发布者签名、信任目录、自动下载与完整迁移回滚机制。公开第三方生态开放前，应分别设计这些能力，不应把 JSON 格式校验当作发布者身份验证。

## 生命周期与资源边界

- 安装：保存验证后的清单，不启动额外进程。
- 使用：宿主根据模板响应用户动作，统一维护必要状态。
- 显示：界面订阅状态，只有需要展示时才刷新。
- 持久化：状态变化时写本地文件，显示刷新不写盘。

如果未来加入脚本插件，继续使用版本化协议；独立规划按需执行器、超时取消、权限代理和资源预算。不要让现有声明式插件被迫承担脚本引擎或常驻 worker 的基础成本。
